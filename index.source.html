Rubik's Cube as a Computational State-Space Problem

In classical artificial intelligence and combinatorial optimization, the Rubik's Cube is one of the benchmark State-Space Search Problems.

1. Group Theoretic State Space Formulation

Mathematically, every cube configuration is an element of the permutation group:

G = ⟨U, D, L, R, F, B⟩ ≤ S₄₈

The total number of physically reachable distinct states is:

|G| = (8! × 3⁷ × 12! × 2¹¹)/2 = 43,252,003,274,489,856,000 ≈ 4.33 × 10¹⁹ states

2. God's Number & Search Complexity

In 2010, mathematicians and computer scientists proved that God's Number is 20 in the Half-Turn Metric (HTM). This means that every single state in the 43 quintillion state space can be solved in at most 20 moves.

However, because the branching factor is b ≈ 18 (or 15 without immediate inverses), an exhaustive Breadth-First Search (BFS) to depth 20 would require checking:

b^d ≈ 18²⁰ ≈ 1.27 × 10²⁵ nodes

This exponential explosion makes brute-force search impossible for deep scrambles without heuristic pruning (A*, IDA*) or hierarchical sub-goal reduction (CFOP / Kociemba 2-phase).

3. Algorithms Implemented in this Project

  • BFS (Breadth-First Search): Explores all states level-by-level to demonstrate the exponential frontier expansion and finds the mathematically optimal shortest path.
  • IDA* (Iterative Deepening A*): Evaluates paths using f(n) = g(n) + h(n) with an admissible heuristic based on misplaced cubies and orientation invariants.
  • Hierarchical CFOP Solver: Decomposes the search into 7 sequential sub-goals: White Cross → First Layer Corners → Middle Layer Edges → OLL Yellow Cross → OLL Yellow Corners → PLL Corners → PLL Edges. Solves any scramble in milliseconds!
